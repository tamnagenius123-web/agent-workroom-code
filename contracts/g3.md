## Scope and explicit decisions

Seven actions: task create/get/claim/renew/submit/cancel/approve. States: open, in_progress, blocked, review, done, canceled. Task goal, optional owner (assignment only), ordered dependencies, pinned input_versions and done_conditions are immutable after create. Task version starts at 1 and increments on each successful mutation after creation, including renew. Execution lease is a separate row with holder_id, lease_epoch and expires_at_ms. No task edits, automatic scheduling, background reallocation, list/search, reject-review, reopening terminal tasks or external execution management.

Lease is exactly 30 seconds for synthetic local tests, not a production recommendation or verified client renewal capability. SQLite server clock inside the atomic transaction decides validity; request time/expiry/actor fields reject. claim increments lease_epoch (initial 0); renew preserves epoch. All mutations after create require expected_version. claim/renew/submit additionally require the observed lease_epoch (claim permits initial 0). Valid lease means holder is authenticated caller, task in_progress and expires_at_ms > database now. Explicit claim may take open/blocked or expired in_progress; no automatic reassignment. An assigned owner must be the claimant; unassigned tasks may be claimed by any active writer with agent role. Dependencies must all be done at claim time. Existing dependencies and pinned message revisions must belong to this room; dependencies only point backward to existing tasks, preventing cycles by construction. Pinned inputs do not silently track later revisions.

submit disposition review (default) or blocked; blocked requires a nonblank reason. Both require an exact existing message_id/artifact_revision in this room authored by the claimant. Submissions are immutable snapshots. review sets current_submission_id; blocked clears it and keeps the immutable blocked submission for audit. Submit ends the execution lease. Explicit claim may resume blocked work. Agents can reach review/blocked, never done. Approve requires expected_version, current submission_id and matching artifact_message_id/artifact_revision; it approves that immutable revision even if a newer message revision exists. Approval is a human attestation of done_conditions, not automated evaluation of text. Owner assignment grants no reviewer rights.

Late submissions after expiry, cancel or re-claim are rejected with LEASE_CONFLICT/409, outcome=not_applied, CLI exit5. This slice does NOT accept or retain separate late results: no late endpoint, history_only response or late_submission_id. Thus no alternate path can bypass revoked membership. A prior same-key committed result remains recoverable as a historical operation snapshot, without changing current task/result; task get is authoritative for current state. Conflicting reuse returns IDEMPOTENCY_CONFLICT even after later transitions. The operation snapshot describes when it was committed, not a renewed assertion of current canonical state.

cancel is allowed to task creator or synthetic user reviewer with write membership, from open/in_progress/blocked/review only, requires expected_version and reason, sets canceled, clears current_submission_id, fences lease by incrementing epoch and expires it. done/canceled are terminal. No stop_confirmed field is fabricated; responses/UI state stop_confirmation=unavailable_no_runner. canceled is a logical state and does not confirm stopping an external process.

## Permission table (all require active principal and active room membership)

| Action | Permission beyond read membership | Fresh-operation state guards (not replay guards) |
|---|---|---|
| get | none | current request read check |
| create | can_post=1 | referenced owner/inputs/dependencies exist |
| claim | can_post=1, principal role agent, owner matches or unassigned | dependency/lease/state/version guards |
| renew / submit | can_post=1, agent role | current holder + epoch + unexpired lease + state/version |
| cancel | can_post=1, creator or role user | nonterminal state/version |
| approve | can_post=1, role user only | review state + exact current submission/artifact/version |

Independent specification review clarification: principal/membership/write/role and creator/user/assignment authority are rechecked atomically for both new writes and replay. Holder/epoch/expiry/version/state/dependency/current-submission guards apply only to a fresh operation, so a successful submit may be historically replayed after it ends its own lease. For renew/submit, simultaneous failure precedence is current authorization → stored-key conflict/historical replay → holder/epoch/expiry/in_progress fencing (LEASE_CONFLICT) → expected_version (VERSION_CONFLICT). Thus stale version combined with canceled/expired/reclaimed always reports LEASE_CONFLICT.

Roles are server-side data, never a header/body claim. New schema-only migration 0003 adds principal_roles (agent/user), tasks, task_leases, immutable task_submissions and immutable task_audit. Fixture loading separately adds synthetic:human with local-human-fixture, active write membership and user role; existing local fixtures are agents. Production entrypoint does not accept any fixture. Owner must be an active writer with agent role in the room at creation. Assignment is not a grant and later revocation still denies the holder. G1/G2 migrations remain byte-identical.

## Atomic persistence and interfaces

One Workroom domain/DB serves REST, CLI and MCP. Reuse one conditional mutation transaction primitive for G2/G3 with canonical recursively key-sorted input hash, explicit caller-scoped action/key, atomic effect/audit/immutable result, replay at quota, and no hidden retry. G1 canonical hashes remain unchanged. G3 operation insert captures a server-clock result snapshot before effects in the same D1 batch; effects consume only that fresh operation ID/snapshot. This avoids updating immutable operations and freezes exact lease/result bytes. Task canonical row, separate lease, submission, audit and operation commit or roll back together. A fresh mutation additionally binds the pre-read task version and lease epoch; a future caller-supplied expected version becoming valid after an intervening claim cannot consume stale task/lease snapshots or roll the holder/epoch backward. Claim explicitly checks the caller-supplied observed epoch as well. Role and membership are rechecked inside the transaction including replay; replay does not bypass removed user authority. Error precedence: current authorization, key conflict/replay if stored, then the fresh-operation guards and explicit precedence above. Read operation recovery requires current read membership, as G1/G2.

All paths under /api/v1/rooms/:room/tasks; POST collection=create, GET /:task=get, POST /:task/{claim,renew,submit,cancel,approve}. POST body has schema_version=1 plus action fields; Idempotency-Key header maps to MCP idempotency_key. Strict request schemas reject actor_id, caller time/expiry, role, arbitrary state/SQL/shell and unsupported fields. Existing room is fixed room_main. No task activity is injected into G2 inbox in this slice (its event kinds remain unchanged).

| CLI | Required fields besides room / explicit key | MCP |
|---|---|---|
| task create --stdin or --file JSON | goal, done_conditions; optional owner=null, dependencies=[], input_versions=[] | workroom_task_create |
| task get --task ID | no key | workroom_task_get |
| task claim --task ID | --expected-version --lease-epoch (initial 0) | workroom_task_claim |
| task renew --task ID | --expected-version --lease-epoch | workroom_task_renew |
| task submit --task ID | --expected-version --lease-epoch --artifact-message --artifact-revision; --disposition review/blocked, --reason for blocked | workroom_task_submit |
| task cancel --task ID | --expected-version --reason | workroom_task_cancel |
| task approve --task ID | --expected-version --submission --artifact-message --artifact-revision | workroom_task_approve |

Task mutation schemas expose the corresponding snake_case fields. CLI create consumes a <=32KiB UTF-8 JSON document through existing stdin/file path. All HTTP bodies retain <=48KiB; text fields <=32KiB; dependencies/inputs/conditions <=20 items (conditions >=1). Duplicate dependency/message-revision references reject. Goal/reasons/conditions are plain untrusted text. Get uses one joined SQL snapshot for task, lease, current submission (or null), database server_time_ms and lease_active; mutation data contains the same committed snapshot and literal action-specific operation. Operation get supports task.create/claim/renew/submit/cancel/approve and binds requested action/key. Every CLI response is one JSON stdout; diagnostics stderr. Existing exit conventions: invalid2/auth3/notfound4/conflict5/rate6/transport unknown7/unsupported8; TASK_CONFLICT, LEASE_CONFLICT, DEPENDENCY_CONFLICT all5. Timeout after dispatch is unknown; use same key or operation get; never automatically retry. MCP tool count becomes 19, official SDK remains pinned 2.3.1.
