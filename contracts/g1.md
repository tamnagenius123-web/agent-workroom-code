# G1 wire contract — schema_version 1

All business responses are UTF-8 JSON objects. Success: `{ok:true,data,meta:{request_id,schema_version:"1",server_time}}`. Mutation/recovery meta also has `idempotency_key,replayed`; lists include `next_cursor,has_more`. Error: `{ok:false,error:{code,message,retryable,outcome},meta}`. Outcomes: not_applied, applied, history_only, unknown. Only applied/not_applied/unknown occur in G1. A persisted message is not delivery acknowledgement, agent execution or approval.

All API/MCP requests require active principal and fixed-room membership. Only members with can_post can mutate. Principals are immutable server identities, not supplied actor_id/role/sender/name. Local fixtures are `synthetic:alpha`, `synthetic:beta` (writers), `synthetic:reader` (reader), and `synthetic:outsider` (no membership). No Muse/Grok/dot identity is created. Fixed room `room_main` is provisioned only by local seed.

| CLI | REST under /api/v1 | MCP tool |
|---|---|---|
| capabilities | GET /capabilities | workroom_capabilities |
| whoami | GET /me | workroom_whoami |
| room read --room room_main [--cursor C] [--limit 50] | GET /rooms/room_main/messages?cursor=C&limit=50 | workroom_room_read |
| message post --room room_main (--stdin or --file PATH) --idempotency-key KEY [--content-format markdown] | POST /rooms/room_main/messages, Idempotency-Key header | workroom_message_post |
| operation get --operation message.post --idempotency-key KEY | GET /operations/message.post/KEY | workroom_operation_get |

Post JSON: `{schema_version:"1",text:string,format:"text"|"markdown"}`; format defaults to text. MCP post adds `room` and `idempotency_key`; other tool inputs require schema_version. Strict schemas reject unknown fields. Maximum UTF-8 text 32768 bytes; nonblank, preserved exactly, no NUL/unpaired surrogates. Entire HTTP body is capped at 49152 bytes including JSON escaping. Markdown is stored and displayed as literal text; HTML is never rendered, images/links never loaded or auto-fetched.

Key: 8–128 ASCII letters/digits/underscore/hyphen/dot. Scope `(principal,"message.post",key)`. Hash: SHA256 of canonical validated JSON `{schema_version,room,text,format}` in that order, including default format. Same key and hash returns original data; different hash -> 409 IDEMPOTENCY_CONFLICT, outcome not_applied for the conflicting request. Conflict details identify only the caller's operation lookup. Request IDs vary on retries; stored result data does not. Operations retained indefinitely in G1.

Read returns oldest-first `{messages}` using server-issued room-bound base64url cursor over sequence, default 50/max 100. Cursor is an offset, not authority. No snapshot guarantee across pages; immutable ascending sequence prevents misses of later inserts. Invalid cursors/limits reject. Other rooms and outsiders return the same 403 FORBIDDEN without revealing existence. Operation get is principal-scoped, rechecks current membership, returns original `{message,operation}`; 404 for absent operation means no recorded commit at that read instant. It does not cancel an in-flight request. Retry the identical request/key if needed.

Bounded writes: at most 60 new posts per principal per server UTC minute. Rate accounting is in the same transaction; replay bypasses rate consumption. 429 includes retry_after and Retry-After; CLI does not automatically retry. Query work is bounded (max 101 read rows, constant count per mutation). Request rate limiting before authentication is deferred with real hosting auth.

CLI uses WORKROOM_URL; synthetic auth only via WORKROOM_LOCAL_TOKEN environment variable to exact loopback http. No secret flags, URL userinfo/query/fragment, cross-origin redirects or hosted synthetic auth. Production auth is unsupported (exit 8). stdout exactly one JSON; diagnostics stderr. Reads default timeout 10s, writes 15s, --timeout seconds up to 60. No implicit retries. Timeout/network after a mutation begins returns outcome unknown; requery/retry with the same key. SIGINT -> 130, unknown if sent. Codes: 0 success; 1 internal; 2 input; 3 auth; 4 missing; 5 conflict; 6 rate; 7 temporary/unknown; 8 unsupported; 130 interrupted.

MCP stateless POST /mcp uses SDK 2.3.1 and protocol 2026-07-28, server/discover, tools/list, tools/call. Modern requests require MCP-Protocol-Version and Mcp-Method, plus Mcp-Name for tools/call. params._meta contains io.modelcontextprotocol/protocolVersion and io.modelcontextprotocol/clientCapabilities. Official client 2.3.1 requires explicit versionNegotiation mode auto (default is legacy). JSON-RPC ID is not an idempotency key. Tool responses include content text containing business JSON and structuredContent of the same object; domain errors set isError. SDK schema/protocol errors remain MCP errors. Legacy claim-less requests are rejected. No task/inbox/revision tools. GET /mcp unsupported. UI and API require same origin; no CORS wildcard. Actual Sites plugin wire compatibility is pending.
